## 为什么新增运行记录

`thread_id` 标识一段会话，`turn_id` 标识一个用户问题及其后续恢复，`run_id` 标识其中一次实际执行。
例如同一个问题第一次调用失败，恢复时会生成新的 `run_id`，沿用同一 `turn_id`，并用 `parent_run_id` 关联上一次执行。

检查点回答“图执行到哪里”，运行表回答“谁发起、用了什么技能、消耗多少、为何结束”。这两种数据承担不同职责。
失败的模型请求也先记入运行表。恢复时汇总同一轮所有运行的消耗，不能通过不断重试重新获得整轮额度。
模型与工具额度取服务器配置和技能配置的较小值；预算耗尽后需要取消这一轮或删除无待审任务的会话。

`employee_id` 是会话所有者，`initiated_by_employee_id` 是本次实际操作者。经理恢复销售的审批时，两者不同。
运行接口只向所有者和本次操作者开放，不提供消息正文或完整技能快照。

## 一次请求如何执行

1. FastAPI 校验登录身份和请求字段。
2. 获取会话执行锁，校验归属，拒绝向未完成的半轮消息直接追加新问题。
3. `skills.py` 根据显式 `skill_id` 或消息关键词选择技能。无明确新意图时沿用上一轮技能。
4. 建立 `AgentContext`，把技能说明、工具清单、版本摘要保存在可序列化快照里，创建运行记录。
5. 模型节点注入统一规则与当前技能说明，只传入该技能允许的工具定义。
6. 工具节点在后端再次检查整批工具权限，先预留额度，再执行工具。
7. 审批工具成功后进入人工暂停；其他工具结果回到模型，最后提取业务结果返回。
8. 在节点边界检查取消和截止时间，最终记录完成、等待审批、失败、取消或超时。

`AgentContext` 是服务端构造的运行对象，持有控制器等不可持久化对象。图状态只保存 JSON 快照，不保存数据库会话或控制器实例。
客户只能选择技能，不能通过请求传入员工身份、工具列表、审批权限或预算。

## S4 执行控制

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `CHEXU_MAX_RUN_SECONDS` | 60 秒 | 一次活跃执行的总截止时间 |
| `CHEXU_MODEL_TIMEOUT_SECONDS` | 20 秒 | 单次模型请求超时，与剩余总时间取较小值 |
| `CHEXU_TOOL_TIMEOUT_SECONDS` | 5 秒 | 当前数据库工具的语句超时 |
| `CHEXU_DB_LOCK_TIMEOUT_SECONDS` | 2 秒 | 数据库锁等待上限 |
| `CHEXU_MAX_MODEL_CALLS` | 4 次 | 同一用户问题及后续恢复共用 |
| `CHEXU_MAX_TOOL_CALLS` | 6 次 | 同一轮工具调用共用，批量调用逐个计数 |
| `CHEXU_MAX_RUN_RESUMES` | 3 次 | 普通失败执行的显式恢复上限 |
| `CHEXU_APPROVAL_MAX_RESUME_ATTEMPTS` | 3 次 | 审批执行的恢复上限 |

人工等待审批不消耗活跃执行时间；审核后建立新的执行段并重新计算截止时间，但不重置同一轮调用额度。
数据库工具使用 PostgreSQL 的语句超时和事务内 `SET LOCAL`；事务结束后超时配置自动还原。

### 取消的实际含义

运行中的取消接口先返回 `202` 和 `cancel_requested`。工作线程在当前模型或数据库请求返回、超时后观察标记，再收尾为 `cancelled`。
因此取消是协作式的，不承诺瞬间杀死正在执行的调用，也不撤销已经提交的报价。
当前模型使用请求原生超时，数据库工具使用原生语句超时；没有另外启动无法停止的后台线程来假装执行已经终止。

如果取消发生在 AI 已发出工具调用、工具结果尚未写回检查点时，会补齐取消的工具消息，然后结束该轮，避免下一轮产生不完整的工具调用协议。
已失败或超时的最新运行可以直接取消并清理半轮状态；待审批任务使用审批取消接口。审批取消不调用模型，因此不受模型可用性和调用额度影响。

如果服务进程意外退出，运行表可能暂时仍是 `running`。超过截止时间后，恢复接口需要先获取会话锁，确认没有旧执行仍占用该会话，才把它视为遗留执行并恢复。
如果遗留执行已收到取消请求，恢复入口只执行取消收尾。

### 恢复的边界

普通恢复只允许会话所有者操作该轮最新的失败或超时运行，调用 `graph.invoke(None)` 继续未完成节点。
涉及人工审批的运行走原有审批审核/取消接口，普通恢复不能绕过人工决定。
恢复时重新校验当前技能是否启用、原工具是否仍有权限；说明内容与版本沿用原快照。
当前规则要求技能文件调整后重启服务才重新加载。

## S5 文件技能

| 技能 | 场景 | 工具 |
| --- | --- | --- |
| `inventory_match` | 按编号、预算、里程查询库存 | `get_vehicle`、`search_vehicles` |
| `vehicle_compare` | 对比多辆车的已知资料 | `get_vehicle`、`search_vehicles` |
| `quote_assist` | 生成草稿、提交人工审批 | 上述工具及 `create_quote_draft`、`request_quote_approval` |

`skill.toml` 管配置：编号、版本、描述、启用状态、允许工具和调用上限。
`SKILL.md` 管流程：何时查资料、怎样展示对比、何时只能预览、何时提交人工审批。

技能不是独立子 Agent，当前三个技能共用同一张业务图。加载不同技能会改变说明和可用工具。
技能本身不能授予员工额外权限；允许工具还需要与服务端角色策略取交集，经理审批也不会作为模型工具开放。

自动路由是可解释的关键词规则，优先报价，再对比，再库存查询；模糊请求可能选错，接口允许明确传 `skill_id`。
新增技能目录需要引用已注册工具。新增 Python 工具仍需代码注册、权限规则和对应验证，不能只写一个技能文件就执行任意功能。

## 新增接口

所有接口均要求登录，沿用 `Authorization: Bearer ...`。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/skills` | 当前员工可用的技能元数据 |
| POST | `/api/chat` | 可选传入 `skill_id`；返回当前技能和版本 |
| GET | `/api/runs?thread_id=...&limit=20` | 运行列表，用于查询正在执行的运行编号 |
| GET | `/api/runs/{run_id}` | 状态、调用次数、错误类型、父运行 |
| POST | `/api/runs/{run_id}/cancel` | 请求取消，或清理失败/超时的当前轮 |
| POST | `/api/runs/{run_id}/resume` | 恢复失败/超时执行，返回新的运行编号 |

聊天请求示例：

```json
{
  "thread_id": "已创建的会话 UUID",
  "message": "比较刚才第一辆和第二辆的价格与里程",
  "skill_id": "vehicle_compare"
}
```

聊天仍是同步 HTTP 请求。需要在执行中取消时，先创建会话，在另一请求中按 `thread_id` 查询运行列表，再取消对应运行。
暂未实现后台任务队列或流式事件接口。

## 验证范围与后续阶段

单元检查覆盖技能选择、快照、工具参数隔离及已有对话行为。数据库集成检查覆盖真实运行记录、取消、超时、恢复、累计额度、权限和原有审批流程。
`evals/skill_routing.jsonl` 和 `scripts/evaluate_skills.py` 提供可重复的离线路由评估，不证明真实大模型的回答质量。

当前 Harness 已落地 Lead Agent、配置、会话持久化、工具、文件技能、审批、预算、运行控制和事件追踪。
独立中间件接口、长期记忆、沙箱、子 Agent、MCP 集成及更广泛的端到端模型评估留待后续阶段；当前不能把完整 Harness 所有模块都视为已完成。
